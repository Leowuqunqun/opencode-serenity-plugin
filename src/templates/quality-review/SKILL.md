# Skill: {{prefix}}-quality-review — 品质评审

> 基于证据的审查方法论：MR/branch/diff/worktree.

## 用途

对代码变更进行结构化审查，确保：
- 变更范围清晰
- 影响评估完整
- 测试覆盖充分
- 文档同步更新

## 评审流程

1. **范围分析**：diff 范围是什么？涉及哪些模块？
2. **影响评估**：变更会影响哪些下游依赖？
3. **一致性检查**：代码风格、命名规范、架构一致性
4. **测试检查**：是否有对应的测试？测试是否覆盖了边界情况？
5. **文档检查**：是否需要更新参考文档或 README？

## 审查清单

- [ ] 变更范围已明确
- [ ] 影响模块已列出
- [ ] 测试已通过
- [ ] 文档已同步
- [ ] 无硬编码/凭据泄露
- [ ] 命名符合项目规范
